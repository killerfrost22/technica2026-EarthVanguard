# EARTH VANGUARD — Engineering Contract

This file is the contract every module codes against. `docs/GDD.md` (game design) decides content and
numbers; this file decides structure, APIs, mechanics baselines, and how we build and test.
If the two disagree on an API, this file wins. If you must deviate, document it in your module's
`docs/api/<module>.md` and in your final report.

## 0. Product

EARTH VANGUARD is a browser vertical-scrolling space shooter in the spirit of *Lightning Fighter*: the player
flies the XF-9 Starlance jet fighter through space, shooting lasers at enemy jets. It has:

- 5 main missions (`m1`–`m5`), each ending in a huge multi-phase boss; 4 side stories (`s1`–`s4`).
- A light story: a short briefing before each mission, plus crew radio chatter during missions.
- Side stories with choices; the choice decides which skill-tree skill you earn.
- Weapon power-ups (pulse/double lasers, spread, piercing lance beam, homing missiles, shields, bombs).
- An upgrade hangar (credits → armor, fire rate, weapons, etc.) and a skill tree.
- Rescuing humans from escape pods mid-battle (credits; VIP pods unlock side stories).
- Black holes and other space hazards that disturb the player (gravity pull plus lensing visuals).
- Local 2-player co-op (same keyboard or gamepads). Touch, mouse, keyboard, and gamepad controls.
- Synthesized sound effects and music. Glossy sci-fi visuals, all drawn in code.

## 1. Hard constraints

1. Vanilla JavaScript (ES2020) + Canvas 2D + WebGL1. No libraries, no frameworks, no runtime network
   requests, no image or audio files. All art is drawn procedurally; all sound is synthesized with
   WebAudio. Fonts are embedded as base64 woff2 in `src/00_fonts.css` (generated by `tools/fetch_fonts.py`).
2. Must run from `file://` by double-clicking `dist/earthvanguard.html`. That means: no ES modules, no
   fetch/XHR of local files, no workers loaded from files. Classic scripts share one global, `window.SL`.
3. It is also published as a claude.ai artifact (`dist/publish/index.html`). There, `alert/confirm/prompt`
   do nothing (build in-page dialogs), storage can throw (wrap every localStorage access in try/catch,
   fall back to memory), audio may only start after a user gesture, the page must work at phone width
   with no horizontal page scroll, and there are no external links or downloads. The page is a single
   deliberate dark visual world: `:root { color-scheme: dark }` with explicit background and colors.
4. Latest Chrome, Edge, Firefox, and Safari, desktop and mobile. WebGL is optional: if it is missing or
   fails, fall back to plain 2D output without crashing.
5. Performance: 60 fps at High quality on a mid-range laptop with ~600 enemy bullets, ~150 player
   bullets, ~40 enemies and ~1500 particles. Rules:
   - Never use `ctx.shadowBlur`, `ctx.filter`, or `getImageData` per frame. They are allowed only inside
     one-time sprite generation.
   - Pre-render static art into cached sprites. Pool bullets and particles. No per-frame allocation of
     canvases, gradients for every bullet, or large arrays in hot paths. (Cached gradients are fine.)
   - Bound every list (particle cap, bullet cap). No DOM layout work per frame except the radio box.
6. Every JS file is an IIFE: `(function (SL) { 'use strict'; ... })(window.SL = window.SL || {});`.
   Define things only under `SL.*`; create no other globals. Files load in name order (`00_` … `22_`), so
   a file may use earlier files at load time and any file at runtime (after boot).
7. Missing content never crashes the game. Unknown enemy, boss, hazard, background, bullet, sfx, music,
   or radio-line ids log `console.warn` once and fall back to a placeholder or a no-op.

## 3. Build, run, test

- Build: `python3 tools/build.py` writes `dist/earthvanguard.html` (full document) and
  `dist/publish/index.html` (artifact page without the doctype/html/head/body wrapper). When several
  people work at once, build to your own file: `python3 tools/build.py --out dist/dev-<you>.html --no-publish`.
  Each JS file is inlined in its own `<script>` ending in `//# sourceURL=src/<file>`, so errors name the
  real file and line.
- Run headless: `bash tools/run.sh --page "dist/earthvanguard.html?<params>" --steps '<json array>'`.
  Steps: `{"wait":ms}`, `{"eval":"js expression"}` (prints the value; may return a Promise),
  `{"shot":"shots/name.png"}`, `{"key":"KeyX"}` (press+release), `{"down":"KeyW"}`, `{"up":"KeyW"}`,
  `{"click":[x,y]}`, `{"touch":["touchStart",x,y]}`. Flags: `--size 720x1280` (viewport, CSS px),
  `--gpu default|swiftshader` (default uses the real GPU). It prints every console warning and error with
  `src/<file>:<line>` and exits 1 on any console error or exception (`--allow-errors` to continue).
  Screenshots are PNG files: open them with the Read tool and look at them.
- Smoke: `bash tools/smoke.sh` (core) builds, then runs every mission with autopilot + god mode +
  fast-forward and checks errors, entity-count sanity, boss defeat, and mission completion. Screenshots go
  to `shots/smoke/`.
- The bar is zero console errors and zero exceptions in every test.

## 4. Coordinates, time, loop

- Logical playfield `SL.W = 720`, `SL.H = 1280` (portrait 9:16). x grows right, y grows down, origin top
  left. Players live in the lower part; enemies enter from the top (y < 0) or the sides.
- Angles are radians, 0 = +x (right), `Math.PI/2` = straight down (+y).
- Main loop (`21_game.js`): requestAnimationFrame → real dt clamped to 1/30 s → `SL.input.update()` →
  `SL.update(dt)` → `SL.render.frame()`. Game dt = real dt × `SL.time.scale` (slow-mo); 0 during hit-stop
  or pause. Every update function takes dt in game seconds and must integrate with dt (never assume 60 fps).
- `SL.time = { t, real, scale, paused }`: `t` is game seconds since mission start.
- Fast-forward: `SL.debug.sim(seconds)` steps the game at a fixed 1/60 without rendering. Update code must
  never depend on state created inside draw functions.
- Randomness: gameplay uses `SL.rng` (seeded; reseeded at mission start from `?seed` or a time seed).
  Purely cosmetic randomness may use `Math.random`.

## 5. Core gameplay rules (baseline; the GDD tunes numbers)

Player
- Speed 560 px/s; focus (hold) 260 px/s, which also shows the hitbox. Instant response. Visual banking up
  to ±0.35 rad from horizontal velocity.
- Hitbox radius 7 against enemy bullets and beams; body radius 22 against enemy bodies and hazards.
  Pickups use body radius + magnet pull.
- Hull: base 100. Damage hits the shield first, then the hull. Any hit grants 0.5 s of invulnerability
  (flicker). Hull ≤ 30% emits `lowHull` once, re-armed when healed above 40%.
- Lives: a shared pool per mission: Cadet 5, Pilot 3, Ace 2, plus upgrade bonuses. When hull reaches 0
  the player is down:
  - Solo: lose a life, explode, respawn after 1.2 s at bottom center with full hull, 2.5 s of
    invulnerability, and weapon level −1 (minimum 1). No lives left means the mission fails.
  - Co-op with a partner alive: the jet ejects a pilot pod that drifts. The partner has 8 s to fly over
    it, which revives the player there with 50% hull and costs no life. On timeout a shared life is spent
    and the player respawns after 1 s. With no lives left that player stays out; the mission fails only
    when both players are out.
- Auto-fire is on by default (setting). Fire, bomb, skill, and focus come from input (section 6.3).
- Bombs: start with 2 (+upgrades), max 5. A bomb is a 2.0 s nova: it clears every enemy bullet on screen
  (turning them into credit sparks), deals 400 damage to every non-boss enemy on screen and 2% of max HP
  (capped at 600) to bosses, and grants 1.5 s of invulnerability, plus a big shockwave and flash.
- Weapon levels run 1–5 per primary type. Picking up a different type switches type and keeps the level;
  the same type adds +1 level (at max: bonus score and credits).
- Damage to players: small bullet 8, medium 12, large 18, enemy beam 45/s, body contact 20, all ×
  `SL.game.diff.damage`.

Difficulty (`SL.game.diff`, set at mission start from `save.difficulty`; co-op also multiplies enemyHp by 1.35)

| | cadet | pilot | ace |
|---|---|---|---|
| bulletSpeed | 0.8 | 1.0 | 1.15 |
| fireRate (enemy) | 0.75 | 1.0 | 1.25 |
| damage | 0.6 | 1.0 | 1.4 |
| enemyHp | 0.85 | 1.0 | 1.15 |
| lives | 5 | 3 | 2 |
| credits | 1.0 | 1.0 | 1.25 |

Scoring
- Each kill gives `def.score × multiplier`. The multiplier starts at ×1.0 and gains +0.1 per kill within a
  2.5 s chain, up to ×8.0; getting hit resets it to ×1.0. A rescue adds 500 × multiplier.
  A boss kill gives its score plus a time bonus.
- The results rank (S/A/B/C/D) comes from hits taken, rescue rate, kill rate, and lives lost
  (formula in `21_game.js`; the GDD may tune it).

Economy
- Credits drop as gold crystals (`def.credits [min,max]`) and are collected by touch or magnet: crystals
  drift toward a player within the magnet radius (base 90 px). Mission-end bonuses come from the GDD.
  Failing a mission keeps 50% of the credits collected in it.

DPS and HP reference (Pilot): pulse L1 ≈ 140 DPS, L5 ≈ 330 DPS; missiles L1 ≈ 40, L3 ≈ 110; a fully
upgraded late-game jet ≈ 700 total. Enemy HP: popcorn 20–35, fighter 60–100, gunship 250–450,
heavy 800–1500, mini-boss 3000–6000, bosses from ~9k (m1) to ~45k total (final). Boss fights target
60–120 s.

## 6. Module APIs

Core implements everything in 6.1–6.9 and 6.11–6.12 and ships working stubs for every content file so
the game runs end to end before content lands. Content modules (6.10) replace their stub files completely.

### 6.1 `00_core.js`

- `SL.W`, `SL.H`, `SL.VERSION`.
- `SL.util`: `clamp, lerp, invLerp, remap, smoothstep, approach(cur, target, maxDelta), dist(ax,ay,bx,by),
  dist2, angleTo(ax,ay,bx,by), angleDiff(a,b), wrapAngle, rotate(x,y,a) → {x,y}, fmtInt(n) → "12,345",
  fmtTime(sec) → "1:05", warnOnce(key, ...msg), deepMerge(a,b)`.
- `SL.ease`: `linear, inQuad, outQuad, inOutQuad, outCubic, inOutCubic, outBack, outElastic, outExpo`.
- `SL.color`: `rgba(hex, a)`, `mix(hexA, hexB, t) → hex`, `hsl(h,s,l,a)`, `lighten(hex, amt)`, `darken(hex, amt)`.
- `SL.makeRng(seed) → { next() in [0,1), range(a,b), int(a,b) inclusive, pick(arr), chance(p), sign(), gauss(), seed(n) }`;
  `SL.rng` is the gameplay instance.
- `SL.bus`: `on(evt, fn) → off()`, `once`, `off`, `emit(evt, data)`. Listener errors are caught and
  `console.error`'d with the event name; they never break the emitter.
- `SL.registry(kind) → { kind, defs, define(id, def), get(id) (warns once, returns null if unknown), has, ids(), all() }`.
  Created here so any file can register at load time: `SL.enemies, SL.bosses, SL.hazards, SL.backgrounds,
  SL.missions, SL.formations, SL.pickupTypes, SL.ebulletTypes, SL.pbulletTypes, SL.screens, SL.sandboxes`.
- `SL.time = { t: 0, real: 0, scale: 1, paused: false }`.
- `SL.onBoot(fn)`: runs once after all scripts are loaded and the DOM is ready, in registration order.
  Content generates sprites lazily on first use, or pre-warms them in onBoot.
- `SL.after(seconds, fn)` / `SL.every(seconds, fn, count?)`: game-time timers, cleared at mission end
  (declared here, driven by `21_game.js`).

### 6.3 `02_input.js`

- `SL.input.players[i]` (i = 0, 1): `{ mx, my` (−1..1 axes), `dragX, dragY` (pointer drag delta in logical
  px this frame; P1 only), `fire, focus` (held), `bomb, skill, pause` (pressed this frame), `any }`.
- `SL.input.menu`: `{ up, down, left, right, confirm, back, pause, any }` pressed-this-frame edges from
  keyboard and gamepads, for the UI.
- `SL.input.update()` runs once per frame before `SL.update`. `SL.input.inject(i, partial)` overrides a
  player's state for the current frame (autopilot, tests). `SL.input.press(i, 'bomb'|'skill'|'pause')`
  queues an edge (touch buttons). `SL.input.setCoop(bool)`. `SL.input.lastDevice`.
  `SL.input.padFor = [padIndexForP1, padIndexForP2]`.
- Bindings (`KeyboardEvent.code`):
  - Solo P1: move WASD and arrows; bomb `KeyX`/`KeyQ`/`KeyK`; skill `KeyC`/`KeyE`/`KeyL`; focus Shift;
    fire (manual mode) `Space`/`KeyZ`/`KeyJ`; pause `Escape`/`KeyP`.
  - Co-op P1: move WASD; bomb `KeyQ`; skill `KeyE`; focus `ShiftLeft`; fire `Space`.
  - Co-op P2: move arrows; bomb `Enter`/`Numpad0`; skill `ShiftRight`/`Numpad1`; focus `ControlRight`/`Numpad2`;
    fire `Slash`/`NumpadEnter`. Either player's `Escape`/`KeyP` pauses.
  - Gamepad (standard mapping): left stick or D-pad move; A bomb; X or B skill; LB/RB focus; RT fire
    (manual mode); Start pause. Solo: any pad drives P1. Co-op: two pads → pad 0 is P1, pad 1 is P2;
    exactly one pad → P2 (P1 keeps WASD).
  - Touch (P1): drag anywhere on the playfield (except buttons) to move the jet by the finger's delta ×
    touchSensitivity (relative, like Lightning Fighter). Auto-fire is forced on. BOMB and SKILL buttons
    are DOM elements owned by ui that call `SL.input.press(0, …)`.
  - Mouse: hold the left button and drag (same as touch). Right-click is bomb (context menu suppressed on
    the game area only).
- Window blur or hidden tab → `SL.game.pause('blur')` during missions. Arrow keys and Space call
  `preventDefault` so the page never scrolls.

### 6.4 `03_audio.js` (core stub; audio owns the real file)

- `SL.audio.unlock()`: create/resume the AudioContext; core calls it on the first pointerdown/keydown.
- `SL.audio.sfx(id, {vol=1, pitch=1, pan, x})`: `x` is a logical x mapped to stereo pan.
- `SL.audio.loop(id, opts) → { set({vol, pitch, pan}), stop(fadeSec) }` for continuous sounds.
- `SL.audio.music(trackId, {fade=1})` crossfades (same track: no-op). `stopMusic(fade)`.
  `duck(amount, seconds)` lowers music for radio lines. `setVolumes({master, music, sfx})`. `ready`.
- SFX and track ids are listed in the GDD's audio section.

### 6.5 `04_render.js`

- DOM: `#app` > `#ambient` (full-viewport canvas: blurred low-res copy of the scene filling the sides) and
  `#game` (9:16 box, centered, `container-type: size`) > `#screen` (WebGL post output, or 2D),
  `#hud` (2D overlay, crisp, not post-processed), `#ui` (DOM overlay: screens, radio, dialogs, touch buttons).
- Sizing: `#game` is the largest 9:16 box that fits the viewport inside the side gutters. `#screen` and
  `#hud` backing stores = CSS size × min(devicePixelRatio, 2). The offscreen scene canvas is 720×1280 × q
  (q = 1 at High and Medium, 0.75 at Low).
- `SL.render.ctx`: scene 2D context, pre-transformed so you draw in 720×1280 logical space (camera shake
  applied by render for world layers). `SL.render.hud`: HUD context in logical space.
- `SL.render.hasGL`, `SL.render.quality` (`'high'|'medium'|'low'`), `setQuality(q)`, and
  `SL.render.distortion` (true when lens/ripple effects actually render). The `'auto'` setting starts at
  High and steps down one level when average frame time exceeds 20 ms over 3 s.
- Per-frame post effects (cleared every frame; add them during update or draw):
  - `addLens(x, y, radius, strength=1)`: gravitational lensing; inside `radius` (event horizon, logical px)
    is black; deflection falls off with distance. Up to 6.
  - `addRipple(x, y, radius, amplitude, width)`: refraction ring for shockwaves. Up to 8.
  - `chromatic(amount 0..1)` (largest this frame wins), `flash(color, alpha)`, `desaturate(amount)`,
    `vignette(amount)` (default 0.35).
- WebGL1 pipeline: scene texture → bright-pass + downsample (¼; ⅛ on Medium) → separable gaussian blur →
  composite with lens and ripple UV distortion → chromatic aberration → + bloom → flash → desaturate →
  vignette → `#screen`. Fallback (no GL, GL error, or Low): scene drawn straight to `#screen`; lens and
  ripple are skipped, so hazards draw their own 2D approximation when `!SL.render.distortion`.
- Draw order (world layers inside `SL.world.draw`): 1 background → 2 hazards `drawUnder` → 3 props, pods,
  pickups → 4 enemies → 5 bosses → 6 allies, players → 7 player bullets and beams (additive) → 8 particles
  → 9 enemy bullets and enemy beams (always on top, for readability) → 10 hazards `drawOver` → post →
  11 HUD on `#hud` (`SL.hud.draw`) → 12 DOM `#ui`.
- Default entity drawing: `def.sprite` via `SL.art.drawSprite` with `e.rot`, `e.scale`, `e.alpha`, plus a
  white hit flash for 0.06 s after damage, unless `def.draw(e, ctx)` exists.

### 6.6 `05_art.js`

- `SL.art.define(key, w, h, drawFn(ctx, w, h), {pad})`: register a generator; it runs on first
  `get(key)` (or pre-warm). Generators may use shadowBlur, filters, and gradients freely. Draw centered.
- `SL.art.get(key) → { canvas, w, h }` (magenta placeholder + warn once if unknown);
  `SL.art.drawSprite(ctx, key, x, y, rot=0, scale=1, alpha=1)` (centered).
- `SL.art.glow(color, radius, {core='#fff'}) → canvas` (cached radial glow: white core → color →
  transparent); `SL.art.drawGlow(ctx, x, y, radius, color, alpha=1)` (additive blit of the cached glow).
- `SL.art.metal(ctx, path, {base, light, dark, angle, rim})`: glossy metal fill lit from the upper left,
  with a darker rim stroke and a specular band. `SL.art.panelLines(ctx, path, color, alpha)`,
  `SL.art.emissive(ctx, path, color, glow)` for glowing seams and lights.
- `SL.art.flame(ctx, x, y, width, length, inner, outer, t)`: animated engine plume pointing +y.
- `SL.art.noise(w, h, {scale, octaves, seed}) → Float32Array` (fbm 0..1);
  `SL.art.noiseCanvas(w, h, {palette:[[t, hex], ...], scale, octaves, seed, alphaCurve}) → canvas`.
- `SL.art.lightDir = {x:-0.6, y:-0.8}`: all art is lit from the upper left.
- `SL.pal`: shared palette (the GDD may extend it):
  `player {hull:'#e8eef7', trim:'#3fc8ff', glow:'#7fe3ff', engine:'#9fe8ff'}`,
  `player2 {hull:'#2b2f3a', trim:'#ffb53f', glow:'#ffd27a', engine:'#ffb070'}`,
  `enemy {hull:'#1c1f2b', hull2:'#3a3f55', seam:'#ff2f6d', glow:'#ff5c8a', engine:'#ff7a3d'}`,
  `ebullet {pink:'#ff4fd8', orange:'#ff8a3d', violet:'#b26bff', red:'#ff3b4f'}`,
  `credit:'#ffd34d'`, `rescue:'#5dffb0'`.

### 6.7 `06_fx.js`

  alpha2=0, blend:'add'|'normal', drag (1/s), gravity, rot, spin, shape:'glow'|'spark'|'square'|'ring'|
  'smoke'|'debris'|<sprite key>, stretch}`. Capped (High 2500 / Medium 1600 / Low 900); oldest dropped.
- `SL.fx.explode(x, y, {size:'s'|'m'|'l'|'xl'|'boss', palette:'enemy'|'player'|'blue'|'green'|'violet'|'gold',
  debris=true, shake=true, sound=true})`: layered flash, fireball, sparks, smoke, debris, ring,
  shockwave (m and up), shake, and `sfx('explode_<size>')`.
- `SL.fx.hit(x, y, color, {dir})`, `SL.fx.sparks(x, y, {count, color, speed, angle, spread, life})`.
- `SL.fx.shockwave(x, y, {radius=260, duration=0.6, strength=1, ring=true})`: ring sprite + render ripple.
- `SL.fx.shake(px, seconds)` (× settings.shake), `SL.fx.flash(color, alpha, seconds)` (30% strength when
  settings.flashes is false), `SL.fx.hitstop(seconds ≤ 0.12)`, `SL.fx.slowmo(scale, seconds)`.
- `SL.fx.text(x, y, str, {color, size=26, life=0.9, rise=60})`: floating text.

### 6.8 `07_world.js`

- `SL.world`: `players[], enemies[]` (bosses too, `e.isBoss`), `pbullets[], ebullets[], beams[]`
  (player beams), `ebeams[]` (enemy beams), `pickups[], pods[], hazards[], allies[], props[]`, `bg`
  (background instance), `scroll {speed, y}`, `bounds {x:0, y:0, w:720, h:1280}`.
- `reset()`; `update(dt)` in order: bg → hazards → players → allies → enemies → bullets → beams →
  pickups → pods → props → collisions → cleanup (remove `dead`; bullets culled 60 px outside the screen;
  enemies with `offscreenKill` culled after leaving the bottom or sides once they've entered).
- Entities are plain objects `{ kind, def, x, y, vx, vy, r, rot, scale, alpha, hp, maxHp, age, dead,
  flash, team, data:{} }`; `def` holds behavior. No class hierarchies.
- Spawning:
  - `SL.spawnEnemy(id, opts) → e`. `opts` (`x, y, vx, vy, path, params, drop, hpMul`, …) goes to
    `def.init(e, opts)`. Def fields: `name, hp, r, score, credits:[min,max], sprite, explosion
    ('s'|'m'|'l'|'xl'), drops, init, update(e, dt), draw(e, ctx), onHit(e, dmg), onDeath(e),
    offscreenKill (default true), contactDamage (default 20), armor (damage multiplier)`.
    `e.invuln = true` makes it ignore damage.
  - `SL.spawnBoss(id, opts) → b`: def from `SL.bosses`; sets `SL.game.boss`; `b.isBoss = true`; emits
    `bossWarning` then `bossSpawn`.
  - `SL.spawnHazard(id, opts) → h`: def `{ init, update(h, dt), drawUnder(h, ctx), drawOver(h, ctx),
    onEnd(h) }`; set `h.dead` to remove.
  - `SL.spawnProp(def, opts)`, `SL.spawnAlly(def, opts)` (team `'ally'`; hit by enemy bullets when
    `def.hittable`).
- Bullets (pooled):
  - `SL.fireEnemy(x, y, angle, speed, type='orb', opts) → b`. Opts: `accel, maxSpeed, minSpeed,
    turn (rad/s), homing (rad/s toward nearest player), homingTime, wave {amp, freq}, delay, life,
    split {at, count, type, speed}, color, scale, damage`. Speed is multiplied by `SL.game.diff.bulletSpeed`
    here. `type` comes from `SL.ebulletTypes` (`{r, damage:'s'|'m'|'l'|number, draw(b, ctx) or sprite,
    spin, orient}`); core registers working defaults (`orb, orbBig, needle, shard, mine`).
  - `SL.firePlayer(owner, x, y, angle, speed, type='pulse', dmg, opts) → b` (`pierce, homing, life,
    scale, onHit`).
  - `SL.world.clearEnemyBullets({toCredits})` (bombs, boss deaths).
- Beams:
  - Player beams: entries in `SL.world.beams` `{owner, x, y, angle, width, length, dps, active, pierce}`;
    collision is segment vs circle; damage per second along the beam (pierce) or to the first enemy hit.
    Weapons owns beam visuals.
  - `SL.fireEnemyBeam(src, {angle, width, length=1600, telegraph=0.8, duration=1.2, sweep, color,
    follow}) → beam`: thin warning line during the telegraph, then active (45/s × diff.damage against the
    hitbox). Core draws a default glossy beam; patterns may restyle it via `SL.ebulletTypes.get('beam')`.
- Damage and queries:
  - `SL.damageEnemy(e, amount, {by, x, y, type})`: armor, invuln, hit flash, small hit fx, `enemyHit`;
    on death `def.onDeath` or the default (explosion, `SL.pickups.drop(e)`, `SL.game.addScore`,
    `enemyKilled`).
  - `SL.damagePlayer(p, amount, {source})`: shield, i-frames, events, fx (chromatic + shake), down logic.
  - `SL.world.nearestEnemy(x, y, {maxDist, onscreen})`, `nearestPlayer(x, y)`, `enemiesInRadius(x, y, r)`,
    `onScreen(e, margin)`.
  - `SL.world.applyGravity(x, y, strength, radius, {players, bullets, enemies, pickups})`: black-hole
    helper; the player pull goes through `SL.player.push`.

### 6.9 `08_player.js`

- `SL.player.create(index, stats) → p { index, x, y, hull, maxHull, shield, maxShield, bombs,
  weapon:{type:'pulse', level:1}, missiles, invuln, alive, down, focus, bank, push:{x,y}, stats,
  skill:{id, cooldown, active, t} }`.
- `SL.player.update(p, dt)`: movement from `SL.input.players[p.index]`, clamped 16 px inside the
  playfield; external push velocity (decays 3/s); firing via `SL.weapons.update(p, dt)` (else a default
  twin pulse); bombs; skills via `SL.skills.activate(p)` and `SL.skills.update(p, dt)`; timers; regen.
- `SL.player.draw(p, ctx)`: `SL.weapons.drawShip(p, ctx)` if defined (weapons owns jet art), else a
  placeholder; plus shield bubble, i-frame flicker, hitbox dot while focusing (or always, per setting).
- `SL.player.push(p, ax, ay, dt)` (scaled by `1 - stats.gravityResist`), `heal`, `addShield`, `addBomb`,
  `bomb(p)`, `respawn`, `revive`, `kill`.
- Stats come from `SL.progress.playerStats(save, index)` when defined, else defaults:
  `{ maxHull:100, shield:0, maxShield:60, bombs:2, maxBombs:5, speed:560, focusSpeed:260, fireRateMul:1,
  damageMul:1, magnet:90, missileStart:0, weaponStart:{type:'pulse', level:1}, gravityResist:0,
  damageTaken:1, bonusLives:0, creditMul:1, regen:0, reviveTime:8 }` plus extras skills read.

### 6.10 Content module contracts

- `09_weapons.js`: `SL.weapons = { update(p, dt), drawShip(p, ctx), setType(p, type), levelUp(p),
  onPlayerDown(p) }`; types `pulse` (twin/double lasers), `spread`, `lance` (piercing beam); levels 1–5;

- `10_pickups.js`: `SL.pickupTypes.define(id, {draw or sprite, r, apply(p, pk), magnet, life})` for

  extras). `SL.pickups = { spawn(id, x, y, opts), drop(enemy) }`.
- `11_enemies.js`: every GDD enemy via `SL.enemies.define`; group entrances via `SL.formations.define(id,
  (opts) => [...enemies])`; path helpers `SL.paths`.
- `12_patterns.js`: enemy bullet type visuals (`SL.ebulletTypes.define`) and `SL.patterns = { aimed(src,
  target, {speed, type, count, spread}), fan(src, angle, {...}), ring(src, {count, speed, type, offset}),
  spiral(state, src, dt, {...}), burst, stream, wave, beam(src, {...}), ... }`. Patterns apply

- `13a_bosses.js` / `13b_bosses.js`: `SL.bosses.define(id, { name, title, hp, r, phases:[{ at (HP fraction
  where the phase starts, 1.0 first), name, enter(b), update(b, dt) }], intro(b, dt) → true when done,
  update(b, dt), draw(b, ctx), parts, onDeath(b) })`. The boss is invulnerable during its intro and phase
  transitions (`b.invuln`). The HUD reads `b.name`, `b.title`, `b.hp/b.maxHp`, `b.phaseMarks`. The death
  sequence (~3 s, slow-mo, chained explosions) ends with `SL.game.bossDefeated(b)`.

- `15_backgrounds.js`: `SL.backgrounds.define(id, { init(bg), update(bg, dt, scroll), draw(bg, ctx),
  setPhase(bg, name) })`; layered parallax. Core ships a `'default'` starfield.
- `16_story.js`: `SL.story = { characters:{id:{name, role, color, portrait(ctx, w, h, t, talking)}},
  briefings:{missionId:{...}}, lines:{id:{who, text}}, radio(idOrObj, opts), say(who, text, opts),
  choice(id) → Promise<optionId> }`. Radio lines queue and never spam (cooldowns). The radio box is a DOM
  element in `#ui` (typewriter text, portrait canvas, music ducking, static sfx). `choice()` pauses
  gameplay with `SL.game.pause('choice')`, shows the dialog, records the result in `session.flags` and

- `17_rescue.js`: `SL.rescue = { spawnPod(x, y, {people, vip, kind}), spawnPilotPod(p) }`. Pods drift and

### 6.11 `21_game.js`: states, missions, director

- `SL.game.state`: `'boot' | 'menu' | 'mission' | 'results'`. UI screens sit on top. `SL.game.paused` with
  a reason (`'pause' | 'choice' | 'blur'`).
- `SL.game.session` during a mission: `{ missionId, mission, kind, coop, players, lives, score, mult, multT,
  credits, rescued, podsSpawned, podsLost, kills, enemiesSpawned, hitsTaken, livesLost, bombsUsed, time,
  flags, checkpoint, boss, result }`. `SL.game.diff` holds the five multipliers plus lives.
- `SL.game.coop` (bool, chosen on the title screen), `newGame()`, `startMission(id, {coop, fromCheckpoint})`,
  `retry(fromCheckpoint)`, `quitMission()`, `pause(reason)`, `resume()`, `addScore(points, x, y)`,
  `addCredits(n, x, y)`, `bossDefeated(b)`, `completeMission()`, `failMission()`, `boss`,
  `setMenuScene({bg, player})` (attract-mode backdrop behind menus: background + idle jet).
- Mission flow: `startMission` → world reset → players from `SL.progress.playerStats` → background →
  music → director runs the timeline → boss → `bossDefeated` → 3 s outro (jets fly up, "MISSION
  COMPLETE") → result → `SL.progress.applyMissionResult(result)` → `SL.save.commit()` →
  `SL.ui.show('results', {result, summary})`. Fail → `SL.ui.show('failed', ...)` with retry from
  checkpoint, restart, or star map.
- Director: its clock advances with game dt except while waiting (`waitClear`, `until`, `boss`,
  `choice`). Events are objects sorted by `at` (seconds of director clock):
  ```
  { at, spawn:'enemyId', x, y, opts }
  { at, formation:'vee', enemy:'dart', count:5, x:360, opts }
  { at, hazard:'blackhole', x, y, opts }
  { at, radio:'lineId' | {who, text} }
  { at, pod:{x, y, people, vip, kind} }
  { at, pickup:'weapon_spread', x, y }
  { at, banner:'TEXT', sub:'small text' }
  { at, music:'trackId' }
  { at, scroll:speed }                 // background scroll speed
  { at, bg:'phaseName' }               // calls the background's setPhase
  { at, waitClear:true, timeout:20 }   // hold the clock until no non-boss enemies remain (or timeout)
  { at, until:(session)=>bool, timeout }
  { at, checkpoint:true }
  { at, boss:'bossId' }                // holds the clock until the boss is defeated; then the mission
                                       // completes unless later events have afterBoss:true
  { at, choice:'choiceId' }            // holds the clock until chosen; session.flags[choiceId] = optionId
  { at, call:(session)=>{} }
  { at, end:true }                     // complete the mission
  ```
  Any event may add `if:(session)=>bool` (skipped when false) and `repeat:{every, count}`.
- Checkpoint: snapshot `{clock, event index, players' weapon/bombs/missiles, score, credits}` for retry.
- The boot sequence registers `window.claude?.hot` (snapshot = save data; restore on ready) when present.

### 6.12 `22_debug.js`: test hooks (every module relies on these; keep them working)

- URL params: `mission=<id>` (start directly, skipping menus), `save=fresh|mid|late|full`, `coop=1`,
  `autopilot=1` (P1) or `2` (both), `god=1`, `seed=<n>`, `t=<sec>` (fast-forward after start), `boss=1`
  (skip to the boss event), `screen=<id>` (open a UI screen with sample data), `sandbox=<id>`, `debug=1`
  (fps, frame ms, counts overlay), `quality=high|medium|low`, `nogl=1`, `mute=1`, `difficulty=…`,
  `test=smoke` (in-page suite → `window.__TEST__` and a console summary).
- `SL.debug.state() → { state, screen, missionId, clock, t, fps, frameMs, players:[{x, y, hull, shield,
  lives, weapon, level, alive}], enemies, ebullets, pbullets, particles, pods, hazards,
  boss:{id, hp, maxHp, phase}|null, score, credits, rescued, paused }`.
- `SL.debug.sim(seconds)`: fast-forward with fixed 1/60 steps, no render; autopilot applies.
- `SL.debug.sandbox(id, fn)` registers a sandbox. Every content module registers at least one (for
  example `enemies` spawns each enemy type; `boss:<id>`; `hazard:<id>`; `bg:<id>`; `weapons`; `pickups`;
  `portraits`; `audio` with buttons for every sfx and track; `ui` screens via `screen=`).
- Autopilot (`SL.debug.autopilot(p, dt)` via `SL.input.inject`): dodges enemy bullets within ~140 px
  (weighted by approach), drifts under the nearest enemy or boss, grabs nearby pickups and pods, stays in
  the lower 40%, bombs when hull < 25% with bullets close, and uses its skill when ready.
- Smoke suite (`tools/smoke.sh` → `tools/smoke.mjs`): every mission with
  `autopilot=2&god=1&mute=1&seed=7` (solo and co-op), simulated in chunks. It asserts no exceptions,
  bounded entity counts, the director reaching the boss, the boss defeated within 240 s of sim time, and
  mission completion, with screenshots at 10 s, 60 s, the boss, and the results screen. It prints a table.

### 6.13 Cross-module extensions (adopted from GDD section 22)

These additive names are part of the contract. The owning module defines each one; every other module
calls it by exactly this name and degrades gracefully if it is missing (check before calling).

1. `SL.patterns.target(src) → {x, y, ref}` (enemies): the aim point for "aimed" attacks, normally the nearest
   player; allies or players with `aimBait` can draw fire (GDD 7.4).
2. `SL.pickups.roll(tableId)` and `SL.pickups.tables` (weapons); enemy defs may carry `dropTable` and `dropChance`.
3. `SL.rescue.lose(pod, reason)` and `pod.towedBy` (story/rescue); hazards and enemies call it.
4. `h.gravity = {x, y, pull, range, r}` on gravity hazards and `b.gravity` / `b.gravityList` on bosses, read by
   patterns, progress and missions.
5. `p.data.ionJamT` (hazards write, weapons read) and `p.data.overdrive` (progress writes, weapons read).
6. Mission def fields `tune {bulletSpeed, fireRate}` and `objectives[i].bonus`, ally `def.hudBar`, and
   `session.flags.failReason` (read by the failed screen).
7. `SL.skills.dilate(seconds, scale)` (progress); `SL.story.choices` and the text tokens `{callsign2}` and
   `{pilot}` (story); `mine_field` def methods `rig(h)` and `setDrift(h, px)` and `SL.hazards.shadeRock(x, y,
   opts)` (hazards); `targetId` on mission entities (missions).
8. Progress may replace `SL.game.rank` with the GDD section 15 formula.

## 7. Visual style guide (summary; the GDD has full art direction)

- Glossy, rendered-looking sci-fi like *Lightning Fighter*: metal hulls with strong specular highlights,
  emissive trim, rich additive glows (bloom does the rest), deep space backgrounds with painted nebulae
  and big planets, chunky satisfying explosions.
- Light comes from the upper left. Hull recipe: base gradient + rim + specular band + panel lines +
  emissive lights. Engines: animated plumes with additive glow.
- Readability rules:
  - Enemy bullets are the brightest, most saturated things on screen (white-hot cores; pink, orange, or
    violet halos) and are drawn last.
  - Player shots are cyan/white and slightly translucent.
  - Backgrounds stay dark and desaturated (value < 40%) under the play area; nothing in a background may
    look like a bullet.
  - Pickups have distinct shapes and icons. Pods are white/green with blinking beacons.
- Effects scale: small enemies pop with a quick flash and sparks; big ones chain-explode with debris and a
  shockwave; bosses get a ~3 s death sequence with slow-mo.
- Everything has secondary motion: bobbing, banking, spinning parts, blinking lights, flickering engines.

## 8. Definition of done (every module)

- Zero console errors and exceptions in its sandbox and in missions that use it.
- Looks polished in a 720×1280 screenshot. Open the PNG and look. If it reads as a placeholder, it is not done.
- Holds 60 fps (`?debug=1`, `--gpu default`) in its heaviest scenario.
- Its public surface is documented in `docs/api/<module>.md`.
